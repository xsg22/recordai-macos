# 统一命名迁移

本轮将当前主分支的产品名称、代码类型、文件名、环境变量、CLI、Skill、MCP URI 和服务访问前缀统一为 TalkTuck。命令及 Skill 名为 `talktuck`，MCP 资源为 `talktuck://`，构建参数使用 `TALKTUCK_` 前缀。

现有应用标识 `com.xsg.talktuck`、录音与模型资料目录、录音 ID、段落 ID 和数据字段保持稳定。旧试验版的偏好导入桥接退出当前源码；现有账号凭据不因本轮命名修改而主动删除。外部 Agent 应从新版本重新获取安装说明。

历史验收、旧截图和旧发布材料先按 SHA-256 校验归档，再移出当前目录。过往 Git 提交和已发布安装包保留，当前清单不把旧 PASS/FAIL 改写成新的验证事实。

0.17.2（44）下载复测与本轮源码验证分开记录。下一版使用新的程序、命令与 URI 名称；在新实测绑定完成前，不覆盖既有发布标签，也不宣称已经发布下一版。

## 账号与离线队列

服务前缀改动仅允许同一 HTTPS 来源（测试可用 loopback HTTP）。恢复登录时用新入口核对同一 `userId`，保留 `loginSubject` 和令牌；验证通过才持久化新地址。离线仍可打开已确认账号，保留迁移书签，联网后继续核验。其他来源的凭据不发送。

同步目录按服务地址与 `userId` 隔离。迁移先校验归属、版本、目录链接和目标冲突，再复制文字状态、操作 ID、冲突、游标与原音续传文件，仅改服务字段，最后原子切换目录。原目录保留；重复执行使用摘要标记确认，遇到不明目标或两侧修改则停止同步，防止覆盖离线编辑。文字和原音队列均打开后才清除账号中的迁移书签。

`zsh Scripts/test-service-namespace.zsh` 使用合成数据与内存凭据验证以上边界，不访问用户钥匙串、个人录音或真实短信服务。服务端新增前缀保留旧入口，为既有发行包继续提供服务；不把服务器内部配置或身份信息提交到公开仓库。
