# 构建与发布

当前源码统一使用 TalkTuck，CLI 和 Skill 名为 `talktuck`。主分支准备下一版命名迁移，不覆盖已发布的 0.17.2（44）安装包或标签。

## 构建位置

生成文件和工具缓存放在配置的独立输出目录。可以在新的源码 checkout 中，将 `.build`、`dist`、`.vendor` 配置为指向输出目录的链接；不要覆盖已有目录，不要把模型或依赖二进制提交到源码仓库。编译前设置 `TMPDIR`、`XDG_CACHE_HOME`、`PIP_CACHE_DIR` 和模块缓存位置。不要改动用户的 HOME。

```zsh
zsh Scripts/release.zsh --candidate
```

该命令运行综合回归、优化编译、签名、DMG/PKG 构建和包内容验证，不创建 GitHub Release。应用为 `TalkTuck.app`，主程序为 `TalkTuckApp`；CLI 为 `talktuck`。安装包与校验文件输出到配置的 `dist`。

## 发布门禁

完整 UI 发布要求当前页面的真实视觉与交互证据。主功能验证通道要求与当前源码、运行时和包绑定的新实测记录。历史记录归档后，不允许沿用旧摘要或把检查项自动标为通过；缺少新证据时门禁应拒绝发布。

发布前核对版本、源码提交、安装包摘要和敏感信息。只上传经过验证的包；发布后实际下载，检查 GitHub 摘要、校验文件、DMG/PKG 内容、包内引擎和 CLI/MCP。

确认新包可用后清理本项目过期打包产物，保留当前交付和必要回滚。源码、用户录音、模型、依赖缓存和远端发布资产不在该清理范围内。
