# 构建与发布

从仓库根目录运行：

```sh
PATH="/opt/homebrew/opt/python@3.12/libexec/bin:$PATH" zsh Scripts/release.zsh
```

该脚本检查全部 UI 验收证据，运行综合回归，构建应用及 DMG / PKG，再检查签名、架构、内置 Python 3.12 与语音引擎、SHA-256 和安装包内的实际内容。最终用户无需安装 Python。

开发期间可用 `zsh Scripts/release.zsh --candidate` 构建本地候选包。它不会绕过回归或安装包校验，不会创建 GitHub Release；候选包不能作为全部 UI 验收通过的证明。单独校验已有包可执行 `zsh Scripts/verify-release.zsh`。

默认构建路径为 `.build/release-<去掉点号的版本>/RecordAI.app`，可用 `RECORD_AI_BUILD_APP_PATH` 指定。版本来自 `Resources/Info.plist`，安装包输出到 `dist`。

GitHub 发布使用 [Build macOS release assets](https://github.com/xsg22/recordai-macos/actions/workflows/build-release-assets.yml)。在目标分支运行 workflow，勾选 `publish_release` 后会先执行同一 UI 证据门禁，再构建、回归、校验，最后把四个安装包及校验文件发布为对应版本的 prerelease。未勾选时仅生成保留 7 天的构建产物。

每一页的客户端截图、视觉核对和交互证据必须先真实完成，再更新 `Docs/design-v2/acceptance.json`。缺一页、检查项不全或证据不对应当前源码时，发布失败。结构门禁不能代替实际视觉判断。

确认新安装包可用后，清理本项目过期的本地安装包、校验文件和能确认用途的打包中间目录。保留当前交付包和必要回滚版本；不删除源码、用户资料、模型、依赖缓存或远端 Release 资产。

当前 0.16.0 状态见 [candidate-package.json](design-v2/validation/candidate-package.json) 与 [UI 验收](UI验收.md)。本地候选包已通过包装校验，完整 UI 验收和远端发布尚未完成。
