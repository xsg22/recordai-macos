# 构建与发布

从仓库根目录运行：

```sh
PATH="/opt/homebrew/opt/python@3.12/libexec/bin:$PATH" zsh Scripts/release.zsh
```

该脚本检查全部 UI 验收证据，运行综合回归，构建应用及 DMG / PKG，再检查签名、架构、内置 Python 3.12 与语音引擎、SHA-256 和安装包内的实际内容。最终用户无需安装 Python。

开发期间可用 `zsh Scripts/release.zsh --candidate` 构建本地候选包。它不会绕过回归或安装包校验，不会创建 GitHub Release；候选包不能作为全部 UI 验收通过的证明。单独校验已有包可执行 `zsh Scripts/verify-release.zsh`。

默认构建路径为 `.build/release-<去掉点号的版本>/RecordAI.app`，可用 `RECORD_AI_BUILD_APP_PATH` 指定。版本来自 `Resources/Info.plist`，安装包输出到 `dist`。

GitHub 发布使用 [Build macOS release assets](https://github.com/xsg22/recordai-macos/actions/workflows/build-release-assets.yml)。在目标分支运行 workflow，勾选 `publish_release` 后会先执行同一 UI 证据门禁，再构建、回归、校验，最后把四个安装包及校验文件发布为对应版本的 prerelease。未勾选时仅生成保留 7 天的构建产物。

每一页的客户端截图、视觉核对和交互证据必须先真实完成，再更新 `Docs/design-v2/acceptance.json`。缺一页、检查项不全或证据不对应当前源码时，发布失败。结构门禁不能代替实际视觉判断。

确认新安装包可用后，清理本项目过期的本地安装包、校验文件和能确认用途的打包中间目录。保留当前交付包和必要回滚版本；不删除源码、用户资料、模型、依赖缓存或远端 Release 资产。

历史 0.16.0 本地包状态见 [candidate-package.json](design-v2/validation/candidate-package.json) 与 [UI 验收](UI验收.md)。完整 UI 验收仍未完成。

## 主功能验证版

用户已明确允许主功能验证通过后先发布一版。该通道只创建 `functional` prerelease，发布说明保留 UI 验收状态；完整 UI 发布通道仍保留逐页门禁。

在已提交且工作区干净的受检版本运行：

```sh
zsh Scripts/publish-functional-release.zsh v0.16.1-functional.1
```

本机若使用 SSH，可加 `RECORD_AI_GIT_REMOTE=git@github.com:xsg22/recordai-macos.git`。脚本不覆盖指向其他提交的标签；重复推送同一标签不会重复创建发布。

`Scripts/check-functional-acceptance.py` 要求当前应用源码、语音运行时输入、真实客户端导入/分人/回放/校正/导出证据和已通过的 22 组回归、本地包校验对应。推送标签后，GitHub 会重新运行 22 组自动检查、构建并签名 DMG/PKG、校验实际内容与 SHA-256，然后才发布。

此通道不将 `acceptance.json` 标为通过，不能被描述为全部 UI 页面已验收。语音样本、已知识别错误和未验范围见[本次功能验证发布说明](releases/functional-preview.md)。

0.16.0 已按此通道[发布到 GitHub](https://github.com/xsg22/recordai-macos/releases/tag/v0.16.0-functional.1)。[构建任务](https://github.com/xsg22/recordai-macos/actions/runs/41298526660)的 22 组回归、打包、校验和发布均通过；发布资产又经本机下载校验、包内容核对及包内语音引擎真实推理复测，详见[发布后验证记录](design-v2/validation/functional-release/result.json)。


本地与 CI 另行运行 `python3 Scripts/test-ui-contracts.py`：8 组既有授权、账号、模型与助手契约用隔离夹具执行，不会真实登录或创建远端会议文档。与 14 组录音/资料回归共同构成当前 22 组自动检查。视觉验收仍逐页完成。

0.16.1 新增统一 Agent 接入。当前发布绑定通过 `functional-release-binding.json` 的 `evidenceRoot` 指向独立版本证据目录，保留旧版实测原件。每次发布仍须重新验证当前候选包、主功能和回归；新增 `Scripts/test-agent-setup.py` 同时在本机及 GitHub 验证 CLI/MCP/Skill。
