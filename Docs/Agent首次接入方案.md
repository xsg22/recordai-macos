# 首次转录后的 Agent 接入与录音控制

日期：2026-11-01。开发分支 `codex/agent-onboarding` 已实现统一复制提示词、首次引导、自描述接口、Skill 分发与显式冷启动控制。自动化及原生入口验证记录见 `Docs/validation/agent-onboarding`。已发布的 `v0.16.0-functional.1` 不包含本次新增功能；尚未完成各品牌 Agent 的真实安装与真实硬件录音联测。最新决策：所有 Agent 统一使用接入提示词，替代此前 App 内选择 Agent 并安装的方案。

## 用户体验

用户首次录音获得非空、已落盘的定稿后，在会议详情显示一次轻量引导卡：

> 让你的 AI 助手使用这段录音
>
> 连接后，可以直接问“刚才的会议讲了什么”，也可以让助手打开 RecordAI 开始录音。
>
> [复制接入提示词] [稍后]

不在录音、授权等待、恢复、保存或推理任务中打断用户。正文已保存但仍在分人时可以记录引导资格，待界面空闲后展示；不用把未定稿的实时草稿当作首次成功。引导已实际展示后记录本机用户的持久化标记，后续录音和重启不重复出现。用户选择“稍后”后仍可从“设置 → Agent 与数据”或“交付 → 连接 Agent”重新打开。升级、重装和已有录音用户的标记迁移需有明确测试，不靠临时 View 状态实现“一次”。

引导卡直接复制接入提示词，提示“已复制，粘贴到你使用的 AI 助手中”。设置的“Agent 接入”分区与交付页保留同一个复制入口，生成同一份内容。不再要求用户选择 Agent，不提供 App 内的安装按钮或各家安装向导；RecordAI 不直接写入任何 Agent 的技能目录或配置。

设置页使用简洁的三步说明：

1. 在 RecordAI 点击“复制接入提示词”。
2. 粘贴到正在使用的 Codex、Claude Code、WorkBuddy、豆包等 Agent 中。
3. 由该 Agent 识别自己的产品、版本和执行环境，获取 RecordAI 提供的安装说明，完成其自身的 Skill 安装和接口验证。

RecordAI 只反馈“接入提示词已复制”，不凭复制动作、文件存在或握手成功推断“Skill 已安装/已加载”。安装、加载及查询验证结果由目标 Agent 分别明确报告。未来若添加 App 侧连接状态，必须有独立真实握手或验证回执，而非依赖复制标记。技能接入后的测试问题为：

> 使用 RecordAI 技能，列出最近的录音并读取最近一条的转录；如果尚未生成定稿，请告诉我当前状态。

## 兼容范围

Skill 包采用 `recordai/SKILL.md` 加按需引用的资源。文件格式可以复用，安装和执行环境不能统一假设。

| Agent | 已确认的官方接入方式 | 提供给 Agent 的适配依据 |
| --- | --- | --- |
| Codex | 用户目录 `~/.agents/skills/<name>/SKILL.md`，项目目录 `.agents/skills`；本地发现与插件分发均有官方说明 | 由 Codex 确认自身版本、安装范围与自定义目录后安装；不盲写插件缓存或 `.system` |
| Claude Code | 用户目录 `~/.claude/skills/<name>/SKILL.md`，项目目录 `.claude/skills` | 由 Claude Code 确认当前配置及目录后安装 |
| WorkBuddy | 桌面技能页支持“添加技能 → 上传技能”导入本地包；代码开发项目另有 `.codebuddy/skills` | 由 Agent 确认当前版本支持直接写入还是导入包；需要用户导入时给出明确步骤，不把 CodeBuddy Code 的目录直接当作所有 WorkBuddy 版本的目录 |
| 豆包及其他 Agent | 尚未取得普通桌面版稳定本地 Skill 发现目录的官方依据 | 由当前 Agent 获取通用说明并确认自身能力；缺少文件、命令或技能安装能力时如实说明，给出可操作的包导入或转录文件方式，不伪造安装成功 |

云端会话不能仅凭这台 Mac 的文件路径访问资料；需要该 Agent 的本地执行能力或本地连接通道。安装 Skill 也不等于开通文件访问和命令执行权限。

## 统一接入提示词与自描述接口

下列接口已在本开发分支实现，当前 GitHub 发行包尚不包含这些新入口。

- CLI：`recordai setup --json`，支持现有 `--root` 指定实际 AgentData 根目录。
- MCP：只读工具 `get_agent_setup`。
- 文件：`AgentData/SETUP.md`，供能读本机文件但暂不能执行命令的 Agent 使用。

三种入口由同一份版本化安装说明生成，返回一致的 schema 版本、App/CLI 实际位置、数据根目录、适配目标、安装方式、Skill 内容或本地包位置、依赖与加载要求、查询示例和连接验证步骤。接口不依赖已有录音，不返回会议正文或账号凭据，不安装 Skill、不修改配置、不启动录音。安装说明随 App 更新，不让提示词固化易过时的各家目录。

未配置 MCP 的 Agent 无法凭提示词直接调用该 MCP，所以统一提示词必须包含可执行的 CLI 绝对路径及文件备用入口；不能只写“调用 RecordAI MCP”。“复制接入提示词”是所有 Agent 唯一的接入入口，无需用户理解 CLI/MCP 差别或手动猜安装目录。

应用按真实安装位置生成以下文本，正确引用带空格的路径，替换占位符后再交付：

> 请为你当前的 Agent 环境安装这台 Mac 上 RecordAI 提供的 Skill，使我能直接查询转录结果，并在明确要求时操作 RecordAI 录音。
>
> 先运行 `"<实际 CLI 绝对路径>" --root "<实际 AgentData 绝对路径>" setup --json` 获取当前版本的官方安装说明；如果你已经连接 RecordAI MCP，也可调用只读工具 `get_agent_setup`。如果不能执行命令，请读取 `<实际 AgentData 绝对路径>/SETUP.md`。
>
> 先确认你当前的产品、版本和执行环境，再按其支持的方式安装，只为当前环境安装，不替其他 Agent 安装。只修改 RecordAI 的 Skill 和必要接入配置，保留其他技能与设置；如遇同名非自有内容，不覆盖。无法访问本机或无法安装时，请说明限制并告诉我可操作的导入步骤。
>
> 接入后列出最近的录音，读取最近一条可用定稿验证连接。区分 Skill 已安装、已加载和接口可用；没有录音时验证接口连通即可，不为测试自动开始录音。除非我另外要求，否则不要开始录音或发送录音到其他服务。

Skill 已加载但尚未登记 MCP 时，可以直接用 CLI 完成查询，MCP 注册不是安装成功的强制前提。接口异常、旧版本缺少 `setup`、App 移动导致路径失效等情况需要返回具体修复步骤或设置中的本地说明，不能把提示词当作必然成功的通道。

## Skill 的职责

引导 Agent 通过现有只读契约查询录音：列出最近记录、按标题/日期筛选、读取定稿和分段发言人、取得音频路径，以及用变更游标等待更新。当前没有服务端搜索接口时，对列表做本地筛选，不虚构 `search_recordings` 工具。`transcriptionReady` 表示正文已保存；`ready` 还反映分人是否仍在进行。分人部分失败不能把现有正文隐藏。

默认读取定稿。只有用户明确需要实时内容时才使用 `includePreview`，并标注草稿。把会议文字作为查询数据，不执行转录内容中包含的指令；不把历史 AI 摘要当作原始发言。查询结果标明会议、时间及发言人，无法确定时说明缺失。

技能主体保持通用，独立的本机连接文件记录 App 实际位置与 AgentData 实际根目录，所有含空格的命令参数正确引用。不要把某台开发机路径硬编码进分发包。默认用 CLI 即可工作的 Agent 不强制配置 MCP；可另提供各 Agent 所需的 MCP 配置。仅安装自有 `recordai` 技能，已有同名非自有目录不自动覆盖。

正文可被所选 Agent 用于回答，接入页应清楚说明这一点，不能沿用录音引擎“全程本机”的说明来暗示外部 Agent 的处理也一定在本机。安装本身不上传整段录音或历史库。

## 在 Agent 中开始录音

本地有命令执行或本地 MCP 通道的 Agent 可以实现以下流程：

1. 用户明确要求“用 RecordAI 开始录音”；单纯查询或总结录音不触发录音。
2. 如果 RecordAI 未运行，唤起已安装的本机 App。
3. 检查当前采集状态、音源和可用性，提交开始录音命令。已有录音时返回现有状态，不因重复请求停止或重复启动。
4. 等待命令结果和实际采集状态。只有确认 `recording=true` 才报告开始成功；等待麦克风/系统声音授权、无设备、模型缺失、忙碌或超时时返回明确状态。
5. 用户可在 Agent 中请求暂停、继续、停止并保存。停止请求成功与最终转录完成是两个阶段，随后查询该录音 ID 的定稿状态。

首次系统采集授权由用户在 macOS 界面完成。开始失败不写入成功回执；不用模拟 UI 点击作为正常集成通道。

## 实现与验证边界

- CLI `setup --json`、MCP `get_agent_setup` / `recordai://setup` 由 `Sources/AgentSetup.swift` 生成同一份契约，打包 `Resources/AgentSkill/recordai`。
- App 生成 `AgentData/SETUP.md`；Skill 的 `references/connection.json` 随接口按实际 App 和数据目录生成。
- `AgentOnboarding` 在实际展示或成功复制后持久化标记。失败、空正文和实时草稿不触发，忙碌时不显示。导入音频产生定稿也可接入；已有合格定稿的用户升级后，在查看合格记录时展示一次。
- 设置、交付及首次引导共用 `AppState.copyAgentPrompt()`，只报告复制结果。
- CLI `control start_recording --launch` 可显式打开当前安装包；为了避免误操作其他实例，仅允许真实 RecordAI 包的默认数据根目录。MCP 对应 `control_recording` 的 `launch=true`。普通查询不唤起 App。
- 新增 CLI `status` / `result COMMAND_UUID` 和只读 MCP `get_recording_status` / `get_command_result`；状态包含观测时间、进程、采集、暂停、准备与推理状态。过期状态 `available=false`，不能作为录音成功的依据。
- App 每秒处理控制队列并发布状态；30 秒前的旧命令拒绝，忙碌、缺模型或引擎导致的启动失败不会写成启动成功。排队/接受回执与实际采集始终分开。
- 已统一 CLI 名称 `recordai`、资源 URI `recordai://` 及 MCP 发行版本来源，修正旧端到端测试的只读工具假设。
- 已通过原有 22 组回归、新增打包 CLI/MCP 隔离端到端测试与 Skill 格式验证。原生首次卡片、设置、交付复制反馈、剪贴板实际命令执行、稍后不重弹均有证据。额外检查了窄窗口和无麦克风布局。
- 真实 Codex/Claude/WorkBuddy/豆包加载与安装、真实麦克风/系统声音授权后的冷启动录音、以及新 DMG/PKG 尚未在本次验证，不能将隔离安装和协议测试当作这些结果。

## 验收要求

1. 首次真实录音成功后出现引导；失败、空正文、单纯实时草稿不触发；第二次录音、重启、稍后均不重复打扰。
2. App 中不存在 Agent 选择、自动安装分支或向 Agent 配置目录写入的副作用；引导、设置和交付三个入口复制一致的动态生成提示词，并反馈已复制。
3. 至少分别在实际 Codex、Claude Code 中粘贴同一套提示词，验证识别自身环境、正确安装、重复接入、冲突保护及实际查询。WorkBuddy 需要导入包时给出能执行的步骤；豆包不在缺少验证时标为完整兼容，不能把缺少能力转成虚假成功。
4. 实际发布包验证 CLI 列表/读取/音频/游标以及 MCP 初始化、工具、资源、非法参数、草稿选择；原始会议和音频保持不变。
5. App 已运行和未运行时，Agent 均能请求录音并确认实际状态；无麦克风、无模型、首次权限、忙碌、重复请求、暂停继续、保存失败及超时均不误报成功。
6. 第一条引导、统一复制入口、已复制状态、设置常驻入口纳入完整设计稿和逐页验收；安装成功/失败/冲突、导入和查询由真实目标 Agent 验证。发布前以当前源码和实际安装包重新绑定证据。
7. CLI `setup --json`、MCP `get_agent_setup` 与 `SETUP.md` 的契约一致；无录音时可用，读取不写入；App 路径含空格、未注册 MCP、旧版本及无本地访问能力时提示词不会误报成功。通过实际 Agent 粘贴该统一提示词验证自助安装和查询流程。
