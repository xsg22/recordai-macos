# RecordAI 完整界面设计册 v2.0

打开 [index.html](index.html) 可逐页查看，也可选择“查看全部页面”。所有字体、样式、图标和演示资料均在本地，无需外部字体或网络资源。也可以从仓库目录运行 `python3 -m http.server 8765 --directory Docs/design-v2`，再访问本机 8765 端口。

## 设计依据

延续本次会话已确认的浅色、钴蓝、左侧录音库、中间逐字稿和右侧摘要 / 行动项布局，补齐所有现有入口与关键状态。设计页面与状态清单以 [manifest.json](manifest.json) 为准，共 44 项；[acceptance.json](acceptance.json) 逐项记录最终实现和验收证据。

固定主窗口参考尺寸为 1440 × 900，侧栏 280，详情侧栏 310；页边距 28、卡片圆角 12、主操作圆角 10。基础字号 15，辅助字号 13，主标题 26。窄窗口将右侧内容收进可访问的摘要抽屉，保留全部操作。深色模式使用相同层级与间距，调整表面和文字对比。

导入、保存和第三方授权采用系统或服务方窗口；设计册给出应用负责的文案、操作边界与前后状态，不替换系统安全或授权界面。

## 实现与验收顺序

1. 共享视觉组件、主窗口、首页、搜索和星标。
2. 录音状态、mini 条、设备异常与播放器。
3. 摘要、行动项、相关附件、笔记与助手。
4. 模型、设置、账号、导出同步、恢复与执行追踪。
5. 编辑与确认弹窗、窄屏、深色和键盘导航。
6. 每个编号保存实际客户端截图，核对该页的全部交互项；修复差异后复验。
7. 更新 README 为最终版本的真实界面图，构建、校验、发布新包，再按项目约定清理过期打包产物。

数据回归通过只证明其覆盖的数据与功能行为，不能替代逐页视觉验收。设计册不是客户端截图，README 最终效果图必须来自实际实现。

## 逐页预览与发布门禁

`zsh Scripts/preview-ui.zsh --build-only` 构建隔离预览应用。打开后使用菜单“逐页验收”，按设计册相同的 44 个编号进入页面。预览使用客户端真实组件和独立临时资料；示例音频、行动项、附件、回收站与恢复原轨均为生成数据。模型使用内容与哈希相符的小型测试文件来呈现校验就绪状态，不执行模型推理；下载进度和同步进度属于状态夹具，不能证明网络下载、录音硬件或远端同步成功。账号演示组件只返回本地样例，不能写入外部服务。真实链路需另行验证并写明证据范围。

`python3 Scripts/check-ui-acceptance.py --report` 输出全部未验收项；不带 `--report` 时，任何一页缺失截图、视觉 / 交互记录或当前版本摘要都会失败。`--digests` 输出用于绑定证据的源码及设计摘要。GitHub Actions 在选择发布时执行该门禁，不能省略某页再发布。

每项 `screenshot` 填仓库内实际截图 PNG 或 JPEG 路径，`visualEvidence` 填逐页核对记录路径，`interactionEvidence` 填验证记录路径数组；`sourceDigest` 和 `designDigest` 取自本次受检版本。先完成实际核对，再将该页 `status` 置为 `passed`。全部通过后才将 `overall` 置为 `passed`。这些结构校验只检查证据完整性，不代替人工视觉判断。
