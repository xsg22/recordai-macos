# macOS 0.17.3（2115）功能验收

原生验收使用本机安装的 Apple Silicon 客户端。应用、CLI 和包内引擎的哈希与候选包记录相符。发布门禁绑定应用源码与语音运行时输入。GitHub 工作流从该标签重新打包并复验安装包。

| 场景 | 结果 |
| --- | --- |
| 合成会议导入并开始转录 | 两个合成语音交替发言，四段依序归到两个发言人，导入原音与输入的 SHA-256 一致 |
| 按段回放 | 第二段从 7.6 秒开始，播到 13.6 秒自动暂停 |
| 校正与导出 | 保存第二段文字，段落 ID、发言人、时间和原始字幕保持一致。实际导出的原稿 Markdown、校正 Markdown 与 SRT 随附 |
| 分组与 Agent | 原生界面建立分组并归档。退出 App 后，包内 CLI 与 MCP 均能读回同一份校正稿和分组，原音可定位 |
| 英文与中英混合 | 包内引擎对合成音频实际识别及时间对齐。切换英文界面后，录音元数据和 Agent 快照逐字节一致 |
| 长录音恢复 | 同一构建复核约 2 小时 28 分钟录音的 19 个批次，覆盖完整，批次归属无重叠，原音与已定稿文件哈希一致 |
| mini 悬浮窗 | 同一构建以系统音源录制 18 分 24 秒，观察到实时字幕、17 次快速修正、录中完成 2 批，停止后补齐尾段，采集与定稿覆盖帧数一致 |

导入、编辑、分组、语言和 Agent 测试使用隔离资料库和合成音频。截图与导出附件均来自该资料库。长录音和资源复测只汇总结果。16 GiB 测试机上的 TalkTuck 相关进程物理内存占用峰值为 6.92 GiB，系统出现 1 次严重内存压力采样。这是一次录制的观察结果。

验证范围为 macOS 主流程。第三方服务使用本地契约测试覆盖，正式账号同步、逐页视觉验收、Developer ID 签名和 Apple 公证留待对应验收。
