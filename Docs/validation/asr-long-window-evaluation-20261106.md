# ASR长窗口与完整发言批次评估（2026-11-06）

这是选参前的实验记录。后续用户选定参数、英文连续章节补测及实现验证见[按语种设置窗口](asr-language-profiles-20261106.md)。

本轮只扩展隔离测试脚本、记录评估结果，**没有更改应用默认参数或替换本机安装包**。在Apple M6/16GiB上，使用既有Qwen3-ASR1.7B MLX8-bit模型，Python3.12.16、mlx0.32.4、mlx-audio0.5.9。基线88ed2c5b，实际模型试验脚本提交0243278；脚本SHA和模型SHA绑定在冻结计划中。

90项试验均有执行记录：80项完整可评分，5项交换增长保护中止，3项状态探测保护中止，同一英文300秒场景两次生成长度失败。独立收口审计重新计算80份分数，并核对全部音频、模型和脚本哈希；均一致。不能将这份报告称为90项完整转录全部通过。

按完整人工参考发言收集，实验单批上限90秒。6秒目标的实际平均批长为中文单人8.6秒、英文15.3秒，并非每6秒硬切。中文30→45秒仅再少1字，实际平均批长约30→48秒；60秒没有额外减少错误。英文只有632个参考词，不能将小样本差距外推为普遍最优。

本试验以人工参考句边界代替VAD，包含不足目标尾批的刷新，测的是Qwen批次结果。主实时字幕链、VAD端点、界面延迟、冷启动和排队没有作为端到端验收。每项内模型只加载一次；每批冷加载占比仅为估算。

## 失败和资源条件

- 英文300秒两次在594–894秒窗口耗尽4928token预算。复现原始返回有3887词，同一8词序列出现34次、参考全文1次。拒绝评分及部分结果提交，不能以加大预算替代问题诊断。
- 主试验每项交换空间增长超过2GiB保护中止；恢复试验独立计划放宽为4GiB，保留8GiB系统盘余量、低可用内存与录音状态保护。初次日志没有覆盖。
- 状态查询超时、以及直接只读同一runtime.json后新鲜度检查未通过，均作为状态探测中止；没有将它们解释为实际观察到新录音。直接探测保留与CLI相同的schema1、5秒新鲜度、进程存活和必需布尔字段验证。
- `mlx.core.set_memory_limit`是指导值，不是硬上限，实际峰值可超过6/9GiB配置。配置和实际峰值分别报告。
- 中文480秒四条件重复结果仍为35/25/29/39错，240秒双人仍28错。6GiB配置480秒双人仍25错、360秒英文仍78错。重复相同样本只说明本轮执行一致，不增加独立语料。

## 数据、口径和产品边界

中文为AISHELL-1 S0002/S0004公开人工参考：单人24分00.85秒3977字、双人交替24分06.44秒4752字，并构造弱音和白噪声变体。弱音乘0.04，经PCM16量化实测低28.22dB；白噪声实测SNR10.000dB，无饱和样本。英文为LibriSpeech dev-clean四位朗读者1272/1462/1673/174交替，24分07.26秒3757词。每轨不重复源句，但条件之间复用音频，不是独立留出集或自然长会议；训练暴露未知。不外推为粤语、iPhone、Windows或所有机器的准确率。

中文按字、英文按词，忽略大小写和大部分标点，保留英文词内ASCII撇号；数字和缩写未作语义等价归一。D/S/I逐项保存。标点可读性、说话人和时间戳质量未评分。不同窗口切点及现有重叠拼接也会影响结果。

当前产品ASR上限240秒、对齐上限300秒；实时单批30秒、音频缓存60秒。超过这些范围的实验不是可直接上线的参数；如选定长窗，仍须适配对齐、缓存、队列、失败降档及真实录音链路。主字幕应持续显示，延后修正不应延后第一批字幕。

本地完整交付位于外接盘 `Codex/talktuck/qwen-long-window-20261106/deliverables`：交互HTML、完整Markdown报告、JSON数据与校验文件；输入、冻结计划、逐字差异、原始模型返回和日志保留在同任务records/evidence目录。80份可评分结果均重新评分一致，所有原音/模型哈希不变。临时模型/监控/本地服务按任务归属关闭，App和用户录音未被停止。

## 复现入口

使用已安装的MLX环境及rapidfuzz，显式把缓存、临时和输出设到已验证挂载的外接盘；`--output`拒绝覆盖已有结果。人工参考manifest需包含id/path/language/reference/segments/sha256。不得将没有人工稿的16分钟私人录音混入错误率排名。

```sh
python -B Scripts/benchmark-qwen-windows.py \
  --manifest "$BENCHMARK_MANIFEST" --case zh-multi --model "$QWEN_MODEL" \
  --window 480 --memory-gib 6 --output "$BENCHMARK_OUTPUT"
python -B Scripts/benchmark-qwen-live-batches.py \
  --manifest "$LIVE_BENCHMARK_MANIFEST" --case zh-multi-live --model "$QWEN_MODEL" \
  --target 45 --max-batch 90 --output "$LIVE_BENCHMARK_OUTPUT"
```

本轮扩展的仅是benchmark窗口上限、可配置实时批长和诊断进度；没有更改ASRWindowPolicy或Native运行策略。最大输出预算只在benchmark提高至32768，再按16token/秒+128（最少512）分配；所有评分项均未耗尽预算，内部块数及覆盖验证仍保留。
