# Mac 本地 ASR 窗口评估 · 2026-11-06

## 结论与配置

以 `0f3ea2a` 为基线，使用本机 Apple M6、16 GiB 内存、Qwen3-ASR-1.7B 8-bit、固定 `mlx-audio 0.5.9`。保持原音、实时预览主链、转录数据结构和同步协议。

- 实时修正：16 GiB 及以上默认累积目标 6 秒，按完整发言批次提交；单批最多 30 秒以保留已有最长 24 秒的 Paraformer 发言，最多两个待处理批次。基础字幕持续显示，修正结果仍检查原发言 ID、时间范围和过期状态。小内存机器保留原 8 秒目标。
- 录后转录：16 GiB 及以上普通话默认 240 秒、英语 45 秒，重叠 3 秒。其他语种、自动识别和小于 16 GiB 的机器维持 24 秒，避免把未验证场景一并改动。
- 可配置录后窗口为 24/45/60/120/240 秒，实时目标为 6/8/12/16 秒；无效值回到推荐值。配置只影响后续任务，不改已有音频或转录。

## 模型能力、框架与应用限制

[Qwen 官方技术报告](https://arxiv.org/html/2601.21337v2) 明确 ASR 单条最长 1200 秒，强制对齐模型最长 300 秒。此为模型能力，不能推导本机最佳长度。官方效率实验采用 CUDA/vLLM，不能套用到 Mac 的 MLX。

本机实际安装的 MLX 0.5.9 源码默认 `chunk_duration=1200`、`max_tokens=8192`，会按 `chunk_duration` 再切分，并跨内部块共用输出预算。参考 [上游实现](https://github.com/Blaizzy/mlx-audio/blob/main/mlx_audio/stt/models/qwen3_asr/qwen3_asr.py)，本轮以本机安装文件和真实返回值为准。音频编码器内部特征分块不等于转录文本再次分段。

旧应用传输限定 30 秒/480000 帧，生成预算固定 512。现在应用传输明确限制 240 秒，强制对齐单独允许 300 秒；解码预算为 `max(512, min(8192, ceil(seconds*16)+128))`。内部切分阈值高于允许输入长度，同时校验返回块数、覆盖范围和 token 是否耗尽，任何异常都不提交部分结果。MLX 配置独立内存及缓存上限，本机内存预算为 6 GiB。

粤语直接在线字幕仍保留原来的 12 秒短语上限、15 秒库切分阈值和 256 token 耗尽检查；没有粤语人工参考集，本轮没有改它的默认窗口。

## 数据与方法

AISHELL-1 的公开人工标注及音频来自 [OpenSLR](https://www.openslr.org/33/) / [AISHELL 官方数据仓库](https://huggingface.co/datasets/AISHELL/AISHELL-1)，英语来自 [LibriSpeech](https://www.openslr.org/12/) 的 [Hugging Face 小样本](https://huggingface.co/datasets/hf-internal-testing/librispeech_asr_dummy)。两个中文说话人与一个英语说话人的方便子集可能与模型训练重叠，不能作为独立准确率或营销数据。下载音频的 LFS SHA256、参考文本 Git blob 和本机副本均留有校验。

普通话同一音轨构造正常、幅度乘 0.04（约 -27.96 dB）、10 dB 白噪声、两人非重叠轮流发言、短句及约 16 分钟长音轨。构造多人不是自然会议，也未覆盖重叠说话。共 59 组固定切点对比、24 组完整发言批次对比、4 组扩展/复测；所有推理禁用网络，串行使用模型。

中文 CER 使用去标点、空白后的字母/数字字符；英文 WER 使用小写词单元，保留词内撇号。未做数字、缩写的语义归一化，格式差异也可能计为错误。漏字/误字/多字分别是最小编辑对齐的删除/替换/插入，不把输出多寡当作准确率。重复额外统计“插入且与前一输出单元相同”的严格子集，其他重复短语未人工逐条分类。

## 实时修正结果

按完整参考发言累积到目标，下一条将使跨度超过 30 秒时先提交现有批次。人工作品句界只用于模拟客户端 VAD 完成发言，末尾不足目标也在实验中提交；应用录音结束时可能直接交给完整定稿，不保证每个尾句都被实时修正。

| 收集目标秒 | 中文平均实际批长秒 | 中文 p95 推理秒（最高） | 英语 p95 推理秒 | 额外冷进程耗时中位秒 |
|---:|---:|---:|---:|---:|
| 6 | 8.04 | 1.06 | 1.96 | 2.66 |
| 8 | 10.05 | 0.88 | 2.02 | 2.21 |
| 12 | 13.35 | 1.15 | 2.03 | 2.30 |
| 16 | 19.09 | 1.17 | 1.89 | 2.46 |

6 与 8 秒目标在本轮完整发言样本上错误率相同；6 秒平均更早收集完成，代价是更频繁启动修正进程。保持有限排队和原字幕兜底。冷进程为每次重新启动冻结 worker 并加载模型，OS 文件缓存未清空，每档两次，不是设备刚开机的冷启动。

上述不是实际界面的端到端字幕修正延迟：还要加完整发言等待、Paraformer 端点、队列与 UI 呈现。基础字幕与修正层是两条链路；未测物理录音时的延迟、温升、功耗和电池。

## 真实旧录音与链路验证

用户原有约 16 分钟录音只复制到外接盘，用于稳定性验证，没有人工参考稿，准确率明确为空。输出字符数不能用于比较漏字或断言哪个窗口更准确。

| 窗口秒 | 推理秒 | 输出字符数 | 原音不变 |
|---:|---:|---:|---|
| 24 | 55.72 | 3184 | 是 |
| 120 | 52.20 | 3022 | 是 |
| 240 | 56.33 | 3032 | 是 |

冻结后的真实生产 worker 已通过普通话 240 秒、英语 45 秒的完整定稿 → Sortformer → ForcedAligner 路径，正文逐字不变，时间未越过音频边界，输入摘要不变。没有人工词级时间标注，未宣称词级对齐准确率。账号、分组、原音双向同步与段落 ID 的既有契约另外走隔离 HTTP/SQLite 回归；没有更改同步协议或生产数据。

## 复现与边界

源码提供 `Scripts/benchmark-qwen-windows.py` 与 `Scripts/benchmark-qwen-live-batches.py`。音频/参考稿通过显式 manifest 输入，输出路径必须存在且结果文件不能已存在；测试失败不覆盖已有结果。最终可配置的数据、依赖、构建、日志和报告均放外接盘任务目录。初始回归发现 Foundation 忽略 TMPDIR 并使用系统临时目录，锁屏期间词库重读失败，旧基线同样复现；测试已显式采用外接盘路径，并设置引擎临时根后完成最终重跑。未修改产品文件保护设置，也未删除无法确认归属的系统目录。

本次未改本机安装版、未 push GitHub、未发布 Release，未在 iPhone 或其他 Mac 硬件上复测，也未验证自然噪声会议、重叠说话、粤语参考准确率或单条 20 分钟的稳定运行。

## 可配置项及复现

专家选项为 `TalkTuck.asr.offlineWindowSeconds` 与 `TalkTuck.asr.liveTargetSeconds`（macOS UserDefaults，域 com.xsg.talktuck）；当前没有给普通设置页增加复杂参数。录后支持 24/45/60/120/240 秒，实时目标支持 6/8/12/16 秒。重置这两个自定义值后恢复按内存和语种推荐。配置不写进同步数据。

开发测试使用现有锁定 MLX 环境和只用于评估的 rapidfuzz。manifest 包含 cases，每个 Case 有 id、path、language、sha256、reference、segments；segment 包含 start、end、text。音频必须是 16 kHz 单声道 PCM16。无需将测试集、模型或用户音频加入源码仓库。

```sh
# 输出目录和缓存须先放在可写外接盘。每个结果使用新文件名。
TMPDIR="$EXTERNAL/tmp/" PYTHONDONTWRITEBYTECODE=1 \
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
python Scripts/benchmark-qwen-windows.py \
  --manifest "$CORPUS/manifest.json" --case zh-clean \
  --model "$MODEL_ROOT" --window 120 \
  --output "$EXTERNAL/results/zh-clean-120.json"
```

本轮实际推理另由 sandbox-exec 禁止网络，记录独立 case/window 结果及输入哈希。真实录音没有人工参考时仅测稳定性，误差率不计算。
